## AXIOMAS FUNDACIONALES — LA BASE FILOSÓFICA INAMOVIBLE

**A1 — El mercado siempre tiene razón.** El precio es la realidad objetiva. Las opiniones y predicciones son hipótesis que el mercado confirma o invalida.

**A2 — La supervivencia del capital es condición previa a toda rentabilidad.** Un sistema sin capital no puede componer. La preservación no es un objetivo secundario: es el requisito de existencia del sistema.

**A3 — La disciplina supera a la inteligencia.** Un sistema mediocre ejecutado con disciplina perfecta supera a un sistema brillante ejecutado con inconsistencia.

**A4 — No se opera para recuperar pérdidas. Se opera para generar ganancias.** El pasado no existe en el trading. Cada operación se evalúa por su mérito propio en el presente.

**A5 — La inactividad es una posición válida y a veces la más rentable.** Estar flat cuando las condiciones no se cumplen no es falla: es la decisión correcta.

**A6 — El sistema es antifrágil.** No solo sobrevive al estrés: se fortalece con él. Cada pérdida, cada régimen adverso, cada fallo es un dato que hace el sistema más robusto.

**A7 — Lo que no se mide no se gestiona.** Toda afirmación sobre el sistema debe ser cuantificable, verificable y rastreable.

**A8 — La correlación no es causalidad.** El sistema busca causalidad estadísticamente robusta, no patrones espurios.

**A9 — El mercado evoluciona y el sistema también.** Ningún edge es permanente. El sistema monitorea el decaimiento de su propio alfa y renueva sus fuentes de ventaja continuamente.

**A10 — La incertidumbre es gestionable, no eliminable.** El sistema no busca certeza: busca probabilidades favorables con riesgo controlado.

**A11 — Los modelos son aproximaciones de la realidad, no la realidad misma.** Ningún modelo de ML/DL captura el mercado completamente. El sistema trata todos sus modelos con escepticismo calibrado.

**A12 — La complejidad no implica superioridad.** Una estrategia simple y robusta supera a una estrategia compleja y frágil. La complejidad se agrega solo cuando añade valor demostrable.

## 5. STACK COMPLETO DE INTELIGENCIA ARTIFICIAL

El sistema integra nativamente un stack de IA de múltiples capas que opera en todos los niveles de la toma de decisiones.

### 5.1 Machine Learning Supervisado

**Modelos de clasificación direccional:**
- Gradient Boosting (XGBoost, LightGBM, CatBoost) para clasificación binaria long/short/flat.
- Random Forest con importancia de features dinámica por régimen.
- Support Vector Machines (SVM) con kernels RBF para clasificación de señales no lineales.
- Logistic Regression regularizada como baseline y componente de ensemble.
- Cada modelo produce probabilidades calibradas (no solo etiquetas binarias) mediante Platt Scaling o Isotonic Regression.

**Modelos de regresión para predicción cuantitativa:**
- Predicción de magnitud de movimiento esperado por modalidad.
- Predicción de ratio R:R esperado antes de ejecutar.
- Predicción de drawdown máximo esperado por operación.
- Predicción de duración óptima de la posición.

**Modelos de ranking:**
- LambdaRank / LambdaMART para ordenar oportunidades por calidad esperada cuando múltiples señales compiten por el capital disponible.
- Produce un ranking de oportunidades que la Capa 6 usa para priorizar capital en situaciones de competencia.

### 5.2 Machine Learning No Supervisado

**Clustering de regímenes de mercado:**
- K-Means, DBSCAN y Gaussian Mixture Models para identificar regímenes de mercado sin etiquetado manual.
- Los clusters son analizados post-hoc para asignarles características operativas (tendencial, lateral, volátil, etc.).
- Permite descubrir sub-regímenes que el análisis manual no identificaría.

**Detección de anomalías:**
- Isolation Forest para detectar condiciones de mercado anómalas que podrían invalidar las suposiciones de las estrategias.
- One-Class SVM para detectar condiciones fuera de distribución en el feature space.
- Local Outlier Factor (LOF) para detectar anomalías locales en el order book.
- Autoencoder variacional para detectar patrones de mercado nunca vistos.

**Reducción de dimensionalidad:**
- PCA y t-SNE para visualización e inspección del feature space.
- UMAP para reducción preservando estructura local: permite detectar relaciones entre features que no son linealmente visibles.
- Factor Analysis para descomponer el mercado en sus factores subyacentes de riesgo.

### 5.3 Deep Learning

**LSTM (Long Short-Term Memory) y GRU:**
- Predicción de dirección de precio en múltiples timeframes simultáneamente.
- Modelado de dependencias temporales de largo plazo en series de precio, volumen y orderflow.
- Arquitectura multi-horizon: un solo modelo predice múltiples horizontes temporales.
- Dropout y regularización L2 para prevenir overfitting.

**Transformer para series temporales:**
- Temporal Fusion Transformer (TFT) para predicción multi-horizonte con manejo nativo de covariables estáticas y dinámicas.
- Attention mechanism para identificar qué períodos históricos son más relevantes para la predicción actual.
- Informer y PatchTST para series temporales de largo contexto con complejidad computacional reducida.

**Redes Convolucionales (CNN) para reconocimiento de patrones:**
- CNN 1D sobre series de precio, volumen y features para detectar patrones recurrentes.
- Detección de formaciones chartistas clásicas (head & shoulders, double top/bottom, flags, wedges, triangles) como features automáticos.
- CNN 2D sobre representaciones de imagen del price action (candlestick charts convertidos a matrices) para capturar patrones visuales.

**Autoencoders:**
- Autoencoder variacional (VAE) para aprender representaciones comprimidas del estado del mercado.
- El espacio latente del autoencoder es usado para detectar cambios de régimen (cuando el estado del mercado sale del espacio latente habitual).
- Autoencoder de reconstrucción como detector de anomalías: alta pérdida de reconstrucción = condición de mercado inusual.

**Redes de Atención Multi-Head:**
- Self-attention para capturar relaciones entre múltiples pares de cripto simultáneamente.
- Cross-attention entre features de diferentes fuentes (precio, volumen, on-chain, sentimiento).
- Permite que el modelo entienda cómo los movimientos en BTC afectan a las altcoins en tiempo real.

**Modelos de predicción de volatilidad:**
- GARCH, EGARCH, GJR-GARCH para predicción de volatilidad condicional.
- Neural GARCH: arquitectura que combina LSTM con la estructura de GARCH.
- Realized Volatility (RV) prediction con HAR-RV y extensiones de deep learning.
- Volatility surface prediction para anticipar regímenes de alta/baja volatilidad.

### 5.4 Reinforcement Learning (RL) para Toma de Decisiones

El sistema opera un agente de Reinforcement Learning que aprende a tomar decisiones de trading óptimas a través de la interacción con el mercado simulado y real.

**Diseño del entorno RL:**
- **Estado (State Space):** representación vectorial del estado completo del mercado incluyendo features técnicos, posición actual, capital disponible, portfolio heat, régimen detectado, score de señales activas, y contexto temporal. El estado es normalizado y dimensionalmente reducido para eficiencia.
- **Acciones (Action Space):** espacio de acciones continuo incluyendo (a) dirección: long/short/flat; (b) tamaño de posición: porcentaje del capital elegible; (c) precio de stop; (d) precio objetivo parcial; (e) tipo de orden. El agente aprende a seleccionar la acción óptima en cada estado.
- **Recompensa (Reward Function):** función de recompensa multi-objetivo cuidadosamente diseñada: recompensa positiva por profit neto (fees y funding incluidos), penalización por drawdown, penalización por liquidación (máxima), penalización por sobreoperación, bonificación por consistencia (Sharpe), penalización por riesgo de correlación excesivo. La función de recompensa no se optimiza solo para profit: optimiza profit ajustado por riesgo.

**Algoritmos de RL:**
- **Proximal Policy Optimization (PPO):** agente principal de toma de decisiones. Estable, eficiente en muestra y efectivo en espacios de acción continuos.
- **Soft Actor-Critic (SAC):** agente alternativo con entropía máxima que favorece la exploración y produce políticas más robustas.
- **Twin Delayed DDPG (TD3):** para espacios de acción continuo de alta dimensión.
- **Multi-Agent RL:** múltiples agentes compiten y cooperan simultáneamente, cada uno especializado en una modalidad o par. La Capa 6 coordina a los agentes como un sistema multi-agente.

**Técnicas de estabilidad del aprendizaje RL:**
- Experience Replay con buffer priorizado (PER): las experiencias más informativas se replayan más frecuentemente.
- Target networks: red separada para calcular los valores objetivo, actualizada con lag para estabilidad.
- Curriculum Learning: el agente comienza entrenando en escenarios simples y progresivamente enfrenta escenarios más complejos.
- Imitation Learning: el agente inicialmente imita estrategias probadas antes de explorar mejoras propias.
- Hindsight Experience Replay (HER): aprende de intentos fallidos re-etiquetando objetivos post-hoc.

**Entorno de simulación para RL:**
- Simulador de mercado de alta fidelidad que replica el order book de Binance con latencia realista, fees, funding y slippage.
- El simulador usa datos históricos de Binance con replay realista.
- Market impact modeling: el simulador modela el impacto que las órdenes del agente tienen en el mercado para evitar sobreestimar el desempeño.
- El agente entrena continuamente en el simulador con datos rolling, incluyendo los datos más recientes.

## 6. SISTEMA DE PREDICCIÓN PROBABILÍSTICA

El sistema no produce predicciones binarias. Produce **distribuciones de probabilidad calibradas** sobre los posibles outcomes.

### 6.1 Predicción Direccional con Incertidumbre
- Cada señal generada incluye: probabilidad estimada de que la dirección sea correcta (P_dir), intervalo de confianza de esa probabilidad, y la incertidumbre epistémica vs aleatoria separadas.
- **Calibración de modelos:** los modelos se calibran usando Platt Scaling e Isotonic Regression para garantizar que cuando dicen "70% de probabilidad de subir", efectivamente sube el 70% de las veces en el conjunto de validación.
- **Conformal Prediction:** produce intervalos de predicción con garantías de cobertura estadística formal, independientemente de las suposiciones del modelo.
- **Ensemble probabilístico:** múltiples modelos producen distribuciones independientes que se combinan mediante Bayesian Model Averaging o stacking probabilístico.

### 6.2 Predicción de Volatilidad y Risk Metrics
- GARCH y sus variantes para volatilidad condicional del próximo período.
- Volatilidad realizada intradiaria usando estimadores de alta frecuencia (Yang-Zhang, Rogers-Satchell).
- Predicción de saltos de precio (jump diffusion models) para anticipar movimientos anormalmente grandes.
- El sistema ajusta dinámicamente el tamaño de posición basándose en la volatilidad predicha: a mayor volatilidad predicha, menor tamaño.

### 6.3 Predicción de Régimen con Modelos Probabilísticos
- Hidden Markov Models (HMM) para detección y predicción de regímenes ocultos del mercado.
- Gaussian Mixture Models para modelar la distribución multi-modal de retornos en diferentes regímenes.
- Markov Switching Models para capturar transiciones entre regímenes con dinámica propia.
- El sistema produce en todo momento un vector de probabilidades sobre el régimen actual: [P_tendencial_alcista, P_tendencial_bajista, P_lateral, P_volátil, P_ruptura, P_reversión].

### 6.4 Monte Carlo y Simulación de Escenarios
- Simulación Monte Carlo de 10,000+ trayectorias para cada ciclo de 3 días para estimar la distribución de posibles resultados.
- Calcula: P(alcanzar +100% en el ciclo), P(drawdown > X%), distribución de retorno esperado, percentiles de pérdida máxima.
- **Stress scenarios Monte Carlo:** simula el desempeño del sistema en condiciones adversas extremas (crisis de 2020, colapso FTX equivalente, flash crash, etc.) para cuantificar el riesgo de cola.
- Los resultados del Monte Carlo informan las decisiones de sizing y apalancamiento del ciclo.

### 6.5 Bayesian Inference y Actualización Continua
- El sistema mantiene creencias bayesianas sobre los parámetros clave del mercado (volatilidad esperada, correlaciones, probabilidades de régimen) que se actualizan continuamente con cada nuevo dato.
- Prior informativo: el sistema comienza con priors basados en datos históricos de Binance.
- Likelihood: cada nuevo tick actualiza la posterior.
- La posterior se usa directamente como input para las decisiones de sizing y dirección.
- Gaussian Processes (GP) para regresión sobre el feature space when the uncertainty epistémica es alta.

## 7. MLOPS — GESTIÓN DEL CICLO DE VIDA DE MODELOS

Los modelos de ML/DL tienen su propio ciclo de vida gestionado profesionalmente.

### 7.1 Pipeline de Entrenamiento
- Datos de entrenamiento: histórico rolling de Binance con expansión continua. Los datos más recientes siempre están incluidos.
- **Walk-forward cross-validation:** validación en ventanas temporales sucesivas que nunca se superponen con el entrenamiento. Previene data leakage y overfitting temporal.
- **Purge y embargo:** al crear datasets de entrenamiento/validación, se purgan las muestras temporalmente cercanas al boundary para evitar contaminación por autocorrelación.
- **Feature importance tracking:** se registra qué features contribuyen más a cada modelo en cada período de entrenamiento. Si un feature que antes era importante deja de serlo, es señal de cambio de régimen.
- Automatización completa del pipeline: reentrenamiento programado + reentrenamiento por trigger (degradación de desempeño, drift detectado).

### 7.2 Model Registry y Versionado
- Cada modelo entrenado queda registrado con: versión, fecha, datos usados, hiperparámetros, métricas de validación, y resultado de las pruebas de forward testing.
- Todos los modelos son inmutables una vez guardados. No se modifican: se crean nuevas versiones.
- El historial completo de modelos permite rollback instantáneo a cualquier versión anterior.

### 7.3 Champion/Challenger Framework
- El modelo en producción es el **Champion**. Siempre existe al menos un **Challenger** en shadow mode.
- El Challenger opera en paralelo al Champion, generando señales y predicciones, pero sin ejecutar operaciones reales.
- Métricas del Challenger se comparan continuamente con las del Champion en condiciones reales de mercado.
- Si el Challenger supera al Champion en métricas out-of-sample durante N días consecutivos con diferencia estadísticamente significativa: el Challenger se promueve a Champion y el ex-Champion pasa a Challenger o se retira.
- Esta competencia continua garantiza que siempre esté operando el mejor modelo disponible.

### 7.4 Detección de Drift y Reentrenamiento
- **Feature drift:** monitoreo continuo de la distribución de cada feature mediante tests estadísticos (KS test, PSI). Si la distribución actual se aleja significativamente de la del entrenamiento: alerta de drift.
- **Concept drift:** monitoreo de la relación entre features y target. Si el modelo predice correctamente pero pierde calibración: concept drift detectado.
- **Performance drift:** degradación del Profit Factor, accuracy o calibración del modelo en ventanas rolling.
- Cualquier drift detectado activa el pipeline de reentrenamiento y evaluación del Challenger.

### 7.5 Shadow Deployment y A/B Testing
- Toda nueva estrategia, feature o modelo pasa por shadow deployment antes de afectar capital real.
- En shadow mode, el sistema genera sus señales, calcula sus tamaños de posición y simula su ejecución, pero no envía órdenes a Binance.
- El desempeño simulado se compara con el desempeño real del sistema activo para validar que los supuestos del modelo se cumplen en producción.
- Solo después de N ciclos de shadow deployment con métricas satisfactorias se promueve al sistema de capital real.

## 9. GESTIÓN DE FUTUROS PERPETUOS — BINANCE ESPECÍFICO

### 9.1 Apalancamiento Dinámico e Inteligente
Variable calculada en cada operación por función multivariable: `leverage = f(score_señal, P_dir_modelo, volatilidad_predicha, distancia_stop, fase_capital, portfolio_heat_actual, régimen_actual)`. A mayor calidad y menor incertidumbre, mayor apalancamiento autorizado. Techo de apalancamiento por fase inamovible. Nunca usa el máximo disponible.

### 9.2 Gestión de Liquidación — Línea Roja Absoluta
La liquidación es el evento prohibido. Es un fallo sistémico de primer orden. Para cada posición: precio de liquidación real + precio de liquidación **virtual** más conservador. Margen aislado obligatorio en fases tempranas. Monitoreo continuo del capital total en riesgo de liquidación agregado. Al acercarse al buffer virtual: (1) reduce tamaño, (2) añade margen, (3) cierre parcial, (4) cierre total.

### 9.3 Funding Rate — Costo Estructural Gestionado
Monitoreo en tiempo real de todos los pares. Antes de abrir posiciones con duración esperada >4h: descuenta costo proyectado del profit esperado. Estrategia secundaria de captura de funding cuando las condiciones son favorables. Las ventanas de cobro de funding (cada 8h) están en el calendario de restricciones.

### 9.4 Fees — Control Milimétrico
Preferencia maker sobre taker cuando la urgencia lo permite. Breakeven exacto pre-trade calculado antes de ejecutar. En microscalping: control existencial de fees. Monitorea descuento por BNB y lo integra en todos los cálculos.

### 9.5 Liquidez, Profundidad y Slippage
Opera solo en pares con liquidez suficiente para el tamaño de posición actual. Monitorea el order book en tiempo real: muros, vacíos, absorción. Calcula slippage esperado antes de cada operación. Detecta secado de liquidez como señal de alerta.

### 9.6 Selección Dinámica de Pares
Universo elegible con criterios mínimos por fase. Ranking dinámico de pares actualizado continuamente. No hay par fijo. El sistema rota según oportunidades activas, historial propio de desempeño y condiciones actuales.

### 9.7 Modelos de Impacto de Mercado
A medida que el capital escala, el sistema estima el impacto de sus propias órdenes en el precio. Modelo de Almgren-Chriss para ejecución óptima. Función de impacto permanente y temporal calibrada por par y tamaño. Evita self-slippage en posiciones grandes.

## 10. CATÁLOGO DE ESTRATEGIAS Y FEATURES

El sistema opera más de 150 features y múltiples estrategias agrupadas en las siguientes categorías. Cada una cumple el principio de responsabilidad única.

### 10.1 Estrategias de Momentum y Seguimiento de Tendencia
- **Trend Following Multi-Timeframe (TFTF):** entrada en la dirección de la tendencia del timeframe superior en pullbacks del timeframe inferior.
- **Momentum Breakout con Volumen:** ruptura de niveles de precio relevantes con confirmación de volumen y CVD.
- **Time Series Momentum (TSMOM):** estrategia basada en el retorno pasado de la propia serie como predictor.
- **Cross-Sectional Momentum (CSMOM):** selección de los pares con mayor momentum relativo dentro del universo elegible.
- **Dual Momentum:** combina momentum absoluto (¿el par sube?) con momentum relativo (¿sube más que otros?).
- **Adaptive Trend Following:** adapta su velocidad de seguimiento a la volatilidad actual usando ATR como modulador.

### 10.2 Estrategias de Reversión a la Media
- **Mean Reversion con Bollinger Bands:** entradas en las bandas extremas con confirmación de reversión.
- **RSI Mean Reversion:** entradas en niveles extremos de RSI (oversold/overbought) con confirmación de estructura.
- **VWAP Reversion:** cuando el precio se desvía significativamente del VWAP con volumen decreciente, anticipa retorno.
- **Statistical Arbitrage de Pares:** dos pares con alta correlación histórica divergen: long el rezagado, short el líder, hasta que se cierre el spread.
- **Kalman Filter Mean Reversion:** usa Filtro de Kalman para estimar el "precio justo" dinámico y operar reversiones al mismo.

### 10.3 Estrategias de Estructura de Mercado (SMC/ICT/Wyckoff)
- **Order Block Retest:** precio retesta un Order Block anterior con reducción de velocidad y CVD favorable.
- **Fair Value Gap Fill:** precio entra en un FVG con momentum reducido, anticipando relleno.
- **Break of Structure Continuation (BOS):** entrada en la dirección del BOS con retroceso al nivel roto.
- **Change of Character Reversal (CHoCH):** entrada contraria a la tendencia previa al detectar CHoCH confirmado.
- **Liquidity sweep + Reversal:** precio barre liquidez (stop hunt) y regresa inmediatamente: entrada en la dirección de la reversión.
- **Wyckoff Spring Long:** entrada long en el Spring de un esquema de acumulación con confirmación de volumen decreciente en la caída.
- **Wyckoff UTAD Short:** entrada short en el UTAD de un esquema de distribución con confirmación de CVD negativo.
- **Premium/Discount Zone Scalp:** comprar en discount del rango relevante, vender en premium.

### 10.4 Estrategias de Orderflow y Microestructura
- **Delta Divergence:** precio sube pero CVD cae → posible reversión bajista. Precio baja pero CVD sube → posible reversión alcista.
- **Absorption Pattern:** volumen masivo sin movimiento de precio significativo = absorción institucional.
- **VPIN Spike:** pico en VPIN indica alto flujo informado. Ajusta sesgo según dirección del flujo.
- **Footprint Imbalance:** desequilibrio masivo en el footprint de una vela en zona relevante de estructura.
- **Large Order Detection:** ejecución de orden de tamaño anormal. Seguir la dirección del "smart money".
- **Liquidation Cascade Anticipation:** cuando se acumulan liquidaciones potenciales en cierto nivel, el precio tiende a buscarlo. El sistema anticipa y opera en la dirección del movimiento probable.

### 10.5 Estrategias de Volume Profile
- **POC Bounce:** precio llega al POC de un período relevante y rebota. Entrada en la dirección del rebote con confirmación.
- **Value Area Breakout:** precio sale del Value Area con volumen: entrada en la dirección de la ruptura.
- **Low Volume Node Transit:** el precio viaja rápidamente por un LVN. El sistema anticipa la velocidad del movimiento y ajusta targets.
- **High Volume Node Support/Resistance:** HVN actúa como soporte o resistencia. Entrada en rebotes con confirmación.

### 10.6 Estrategias de Volatilidad
- **Volatility Breakout (ATR):** el precio rompe el rango diario (medido en múltiplos de ATR) con momentum. Entrada en la dirección de la ruptura.
- **Volatility Compression Entry:** Bollinger Bands se comprimen (squeeze). Entrada en la dirección de la expansión cuando ocurre.
- **Bollinger Band Squeeze + RSI:** compresión de Bandas de Bollinger + RSI neutro = coiled spring. Entrada en la dirección del primer movimiento expansivo con volumen.
- **Implied Volatility Equivalent (Options-Inspired):** usa el funding rate extremo y el OI como proxy de "implied volatility" para anticipar movimientos explosivos.

### 10.7 Estrategias de Arbitraje y Funding
- **Funding Rate Arbitrage:** cuando el funding rate es extremo positivo, sesgo short (los longs pagan). Cuando es extremo negativo, sesgo long (los shorts pagan).
- **Basis Convergence:** si la diferencia entre el precio perpetuo y el precio spot se desvía de su media histórica, anticipa convergencia.
- **Cross-Pair Statistical Arbitrage:** pares de cripto con alta correlación histórica divergen temporalmente. Opera la convergencia.

### 10.8 Estrategias de Datos On-Chain
- **Exchange Inflow Alert:** flujo masivo de BTC a exchanges = posible presión vendedora. Aumenta sesgo short.
- **Whale Accumulation Signal:** ballenas acumulan en on-chain = sesgo long con confirmación de estructura.
- **SOPR Reversal:** SOPR cruza por debajo de 1.0 (holders vendiendo en pérdida) con alto volumen = posible capitulación y reversal largo.
- **Stablecoin Supply Ratio:** alta oferta de stablecoins en exchanges = poder de compra disponible = sesgo largo en estructuras alcistas.

### 10.9 Estrategias de Sentimiento
- **Extreme Fear Contrarian Long:** Fear & Greed < 20 + estructura alcista técnica = entrada long contrarian.
- **Extreme Greed Contrarian Short:** Fear & Greed > 80 + estructura bajista técnica = entrada short contrarian.
- **Sentiment Divergence:** precio sube pero sentimiento empeora = posible distribución. Precio baja pero sentimiento mejora = posible acumulación.
- **Narrative Momentum:** cuando una narrativa nueva surge y domina el sentimiento, el sistema puede seguir el momentum hasta agotamiento.

### 10.10 Estrategias de Estacionalidad y Temporalidad
- **Session Bias:** cada sesión de mercado (Tokio, Londres, NY) tiene sesgos estadísticos documentados. El sistema los incorpora como factor de ajuste del score.
- **Day-of-Week Effect:** días de la semana con sesgo estadístico positivo o negativo documentado en el par operado.
- **End-of-Month Effect:** el cierre de mes suele producir rebalanceos institucionales con comportamiento predecible.
- **Pre/Post Funding Window:** comportamiento del precio en los 30 minutos antes y después del funding rate.
- **Monday Gap Fill:** gaps del fin de semana en cripto tienen tasa de relleno estadísticamente documentada.

### 10.11 Estrategias de Micro-Capital Específicas (Fase $13–$100)
- **Single Pair Focus:** en micro-capital, el sistema se concentra en el par de mayor liquidez y volatilidad favorable.
- **High Winrate Conservative:** prioriza estrategias con winrate >65% aunque el R:R sea menor, para mantener el compounding constante.
- **Micro Position Compounding:** opera posiciones muy pequeñas pero múltiples entradas en la misma dirección cuando el contexto es favorable, construyendo la posición progresivamente.

## 11. GESTIÓN CUANTITATIVA DE RIESGO AVANZADA

### 11.1 Estructura de Riesgo Inamovible
- **Riesgo por operación:** porcentaje fijo máximo del capital, ajustado por fase de capital y volatilidad predicha.
- **Portfolio Heat:** riesgo agregado de todas las posiciones simultáneas. Límite máximo permanente. Si se alcanza: no se abren nuevas posiciones.
- **Riesgo por sesión:** drawdown máximo diario. Al alcanzarlo: sistema detenido hasta la siguiente ventana.
- **Riesgo por estrategia:** drawdown acumulado máximo propio. Superarlo: desactivación automática y revisión obligatoria.
- **Riesgo sistémico:** drawdown total del portafolio supera umbral crítico → protocolo de emergencia.
- **Stop loss obligatorio y activo** antes de la entrada. Sin stop: sin trade. Sin excepción.

### 11.2 Value at Risk (VaR) y Expected Shortfall (CVaR)
- **VaR paramétrico:** asumiendo distribución normal (o t-Student para colas gordas) del portafolio, calcula la pérdida máxima al 95% y 99% de confianza para el horizonte temporal de cada modalidad.
- **VaR histórico:** usando la distribución empírica de retornos históricos del portafolio, calcula el VaR sin supuestos distribucionales.
- **Monte Carlo VaR:** simula 10,000+ trayectorias del portafolio para estimar la distribución completa de pérdidas.
- **CVaR (Expected Shortfall):** calcula la pérdida esperada en el peor X% de escenarios. Métrica más robusta que VaR para gestión de riesgo de cola.
- El VaR y CVaR se calculan en tiempo real para el portafolio actual y se usan como inputs para el tamaño de nuevas posiciones.

### 11.3 Extreme Value Theory (EVT) para Riesgo de Cola
- Modela la distribución de las pérdidas extremas usando Generalized Pareto Distribution (GPD).
- Calculates el "Expected Tail Loss" para eventos de muy baja probabilidad (0.1%, 0.01%) que el VaR histórico subestima.
- El sistema usa EVT para dimensionar los buffers de emergencia y los límites del kill switch global.
- Stress testing basado en EVT: simula pérdidas en el percentil 99.9% de la distribución histórica de shocks de mercado cripto.

### 11.4 Factor Models de Riesgo y Atribución
- Descompone el riesgo del portafolio en factores: riesgo de mercado (beta a BTC), riesgo de tamaño (cap small vs large), riesgo de momentum, riesgo de volatilidad, riesgo de liquidez.
- **Risk Attribution:** cuánto de cada unidad de riesgo total contribuye cada estrategia, par y modalidad. Permite identificar dónde se concentra el riesgo.
- Factor de riesgo de correlación: mide cuánto del riesgo proviene de posiciones correlacionadas.

### 11.5 Prohibiciones Absolutas
Inamovibles. Ninguna capa de inteligencia puede justificar infringirlas:
- Nunca mueve un stop en contra de la posición para "dar más espacio".
- Nunca promedia a la baja en una posición perdedora sin plan pre-establecido explícito.
- Nunca opera para recuperar pérdidas más rápido.
- Nunca usa mayor apalancamiento porque "esta señal es segura".
- Nunca desactiva el stop loss bajo ninguna circunstancia.
- Nunca ignora un kill switch o fail-safe.
- Nunca opera en un régimen para el que una estrategia no fue diseñada y validada.
- Nunca integra una pieza sin pasar el pipeline de validación completo.
- Nunca asume que "el mercado tiene que volver".
- Nunca toma decisiones basadas en una sola fuente de señal.

## 12. CÁLCULO CUANTITATIVO AVANZADO

### 12.1 Sistema de Sizing Óptimo

**Kelly Criterion y variantes:**
- Kelly clásico: `f* = (bp - q) / b` donde b=odds, p=probabilidad de éxito, q=probabilidad de fracaso.
- Fractional Kelly (½ o ¼ Kelly): reduce el tamaño recomendado para manejar incertidumbre en la estimación de p.
- Kelly continuo: para distribuciones de retorno no-binarias, usa la versión continua con los momentos de la distribución de retornos.
- **Optimal f (Ralph Vince):** maximiza el crecimiento geométrico de la cuenta usando el trade más perdedor histórico como referencia.
- El sistema calcula Kelly y Optimal f para cada estrategia y usa el mínimo de ambos como techo de sizing.

**Sizing basado en volatilidad:**
- Position sizing inverso a la volatilidad (ATR-based): a mayor ATR del activo, menor tamaño de posición para mantener el riesgo en dólares constante.
- Target Volatility Scaling: ajusta el tamaño de posición para que la contribución de volatilidad de cada posición sea constante en el portafolio.

**Sizing basado en el modelo predictivo:**
- Sizing proporcional a la probabilidad estimada de éxito por el modelo: mayor probabilidad = mayor tamaño, dentro de los límites del Kelly ajustado.
- Sizing proporcional al Edge esperado: `Edge = E[Profit] / Capital_riesgo`. Mayor edge = mayor sizing.

### 12.2 Métricas de Calidad del Sistema

**System Quality Number (SQN):**
- `SQN = (E[R] / StdDev[R]) × √(N)` donde R = retorno por unidad de riesgo, N = número de trades.
- SQN > 2.0: sistema bueno. > 3.0: excelente. > 5.0: excepcional (raro).
- El sistema calcula SQN rolling para detectar degradación temprana.

**Otras métricas de calidad:**
- Profit Factor = Gross Profit / Gross Loss. Mínimo > 1.5 para mantenerse activo.
- Expectancy = (Win Rate × Average Win) - (Loss Rate × Average Loss).
- Expectancy Score = Expectancy × Trade Frequency.
- Calmar Ratio = Retorno Anualizado / Drawdown Máximo.
- Omega Ratio = P(R > threshold) / P(R < threshold) integrado sobre la distribución.
- Ulcer Index: medida del drawdown que pondera tanto la profundidad como la duración.

### 12.3 Análisis de Trayectoria de Trade (MAE/MFE)
- **Maximum Adverse Excursion (MAE):** la máxima pérdida no realizada que el precio alcanzó durante la vida de cada operación, antes de su cierre. Permite optimizar la colocación del stop loss.
- **Maximum Favorable Excursion (MFE):** la máxima ganancia no realizada que el precio alcanzó durante la vida de cada operación. Permite optimizar la toma de ganancias.
- **Análisis MAE/MFE:** grafica MAE vs MFE para todo el historial. Operaciones ganadoras con bajo MAE = stops bien colocados. Operaciones ganadoras con alto MFE pero cierre prematuro = potencial de mejora en gestión de salidas.
- El sistema usa el análisis MAE/MFE para optimizar automáticamente los niveles de stop y targets.

### 12.4 Análisis de Curva de Equity
- **Drawdown analysis:** distribución de drawdowns, duración media, drawdown máximo, recovery time.
- **Run test:** test estadístico para detectar si las rachas de ganancias y pérdidas son aleatorias o tienen correlación serial (¿un win predice otro win?).
- **Equity curve momentum:** el sistema puede reducir el sizing cuando la curva de equity de una estrategia entra en drawdown sostenido (meta-filter).
- **Curva de equity ajustada por riesgo:** normalizada por la volatilidad del sistema en cada período.

### 12.5 Estadísticas por Contexto
El sistema mantiene estadísticas desagregadas por cada combinación relevante:
- Por régimen de mercado × dirección (long/short) × modalidad × par × sesión × hora del día × día de la semana.
- Esta granularidad permite al sistema detectar exactamente en qué contextos cada estrategia funciona y en cuáles no.
- Los modelos de ML usan estas estadísticas desagregadas como features de alta calidad.

## 13. GESTIÓN DE PORTAFOLIO AVANZADA

### 13.1 Hierarchical Risk Parity (HRP)
- Algoritmo de Ledoit-Wolf para estimación robusta de la matriz de covarianza (evita el ruido de las estimaciones muestral estándar).
- **Hierarchical Clustering:** agrupa estrategias por similitud de comportamiento usando clustering jerárquico sobre la matriz de correlación.
- **Risk Parity:** dentro de cada cluster, asigna capital de forma que cada estrategia contribuya igualmente al riesgo total del cluster.
- **Across clusters:** asigna capital de forma que cada cluster contribuya igualmente al riesgo total del portafolio.
- HRP es más robusto que Mean-Variance Optimization (MVO) porque no requiere invertir la matriz de covarianza y es menos sensible a errores de estimación.

### 13.2 Dynamic Portfolio Optimization
- El portafolio se re-optimiza periódicamente (cada ciclo y en tiempo real ante cambios de régimen) usando los retornos y covarianzas más recientes.
- **Black-Litterman Model:** combina el equilibrio de mercado (prior) con las "views" del sistema (predicciones del modelo) para producir retornos esperados ajustados que se usan en la optimización.
- **Robust Optimization:** usa optimización robusta (minimax regret) para producir portafolios que funcionan bien en un rango de escenarios, no solo en el escenario esperado.

### 13.3 Factor Exposure Management
- El portafolio tiene exposición objetivo a factores de riesgo: momentum, volatilidad, liquidez, dirección (long-short balance).
- El sistema monitorea continuamente la exposición actual a cada factor y la ajusta para mantenerla dentro de los rangos objetivo.
- **Factor neutralization:** cuando el sistema quiere ser neutral a un factor (ej: market neutral), ajusta las posiciones para cancelar la exposición neta a ese factor.

### 13.4 Ensemble de Portafolios
- El sistema mantiene múltiples "sub-portafolios" especializados: uno para tendencia, uno para reversión, uno para volatilidad, uno para orderflow.
- La Capa 6 pondera estos sub-portafolios dinámicamente según el régimen actual y su desempeño reciente.
- El portafolio final es un ensemble ponderado de los sub-portafolios.

## 14. INTELIGENCIA DE ESTRUCTURA DE MERCADO AVANZADA

### 14.1 Smart Money Concepts (SMC) e ICT
- **Order Blocks (OB):** zonas donde instituciones colocaron órdenes masivas. Alta probabilidad de respuesta del precio.
- **Fair Value Gaps (FVG):** desequilibrios que el mercado tiende a rellenar. El sistema los usa como targets y zonas de entrada.
- **Break of Structure (BOS):** confirmación de continuación. El smart money sigue comprometido.
- **Change of Character (CHoCH):** señal temprana de reversión potencial.
- **Liquidity pools:** concentraciones de stops que el precio busca antes de moverse en la dirección real.
- **Premium y Discount Zones:** compra en discount, vende en premium del rango relevante.

### 14.2 Wyckoff Methodology
- **Acumulación:** PS (Preliminary Support), SC (Selling Climax), AR (Automatic Rally), ST (Secondary Test), Spring, UTAD.
- **Distribución:** PSY (Preliminary Supply), BC (Buying Climax), AR (Automatic Reaction), UT (Upthrust), UTAD.
- **Rango y Fases:** El sistema identifica la fase del ciclo Wyckoff (A, B, C, D, E) y sesga la dirección en consecuencia.
